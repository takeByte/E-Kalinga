# Admin Integrations Toggle + Google OAuth — Spec

**Status:** Draft, ready for implementation
**Area:** `apps/server` (Express API), `apps/web` (React + TanStack Router)
**Date:** 2026-10-19
**Short name:** `admin-integrations`

---

## 1. Summary

Add an admin-only **Integrations** screen that lists third-party integrations with an on/off switch. Ship **Google sign-in (OAuth 2.0 via Google Identity Services ID tokens)** as the first integration.

An admin can turn Google sign-in on only when the server has valid Google credentials. When enabled, public visitors see a Google entry in the public header and an official Google button on the login page. Google sign-in works **only for existing HealthCentria accounts** — unknown emails are rejected with a clear message. There is no self-service Google registration.

The feature is built on a **generic provider registry** so future integrations can be added without redesigning the API or UI.

---

## 2. Goals

1. New admin page `/admin/integrations` with a per-provider toggle.
2. Persist toggle state in MongoDB, with admin audit trail.
3. Server-side gate: when disabled, Google sign-in is rejected and no Google button is exposed.
4. Full Google sign-in flow for **existing** accounts (all roles: patient, staff, admin).
5. Auto-link a Google identity to an existing account by verified email, while keeping email + password login working.
6. Public header link + official Google button on `/login`.
7. Admin-visible configuration readiness and usage stats (linked accounts, last sign-in).
8. Docs (`README`, `context/tech_stack.md`, `context/user_stories.md`) and env templates updated.

## 3. Non-goals

- Google sign-up / auto-creation of accounts, or profile-completion onboarding.
- More integrations than Google (no Facebook/Apple cards or placeholder providers).
- Account unlink / "disconnect Google" action.
- Audit-log UI or audit API endpoints.
- Google One Tap, auto-select, or silent re-auth.
- Profile photo rendering in the UI (the Google picture URL is stored but unused).
- Disabling or revoking existing JWTs when the integration is turned off.
- Automated test framework setup (no test runner exists in the repo today).

## 5. Current-state facts to build on

- Backend: plain JS ESM, Express 4, Mongoose 8, Zod 3, JWT via `signSession(user)` (`sub`, `role`, `JWT_EXPIRES_IN` default 7d).
- Auth: `POST /api/auth/login` and `/register`; `requireAuth` + `requireRole('admin')` guards admin routes; errors are `{ success: false, message, errors? }`.
- User model requires `passwordHash`; patient profile fields are conditionally required only for patients. Staff/admin accounts have no patient fields.
- Admin pages: `/admin/dashboard`, `/admin/staff-accounts`; sidebar source is `apps/web/src/components/ops-nav.ts` (`adminNav`).
- Web session: localStorage key `healthcentria.session`; `apiFetch` attaches `Bearer` and normalizes `ApiError`.
- Frontend routing is file-based (TanStack Router plugin); `routeTree.gen.ts` is committed and regenerated by dev/build.
- No integration/settings model exists. No switch component exists, but `radix-ui@1.6.7` is installed and exports `Switch`.
- `helmet()` is enabled with default policies. The SPA is served by Vite today, but API-served headers should be made compatible for future production hosting.

## 6. Architecture

### 6.1 Provider registry (server)

New module `apps/server/src/config/integrations.js`:

```js
export const INTEGRATION_PROVIDERS = {
  google: {
    key: 'google',
    label: 'Google',
    description: 'Let existing patients and staff sign in with their Google account.',
    docsUrl: '/README.md#google-sign-in-optional',
  },
};

export function isProviderConfigured(key) {
  if (key === 'google') {
    return Boolean(env.GOOGLE_CLIENT_ID && env.GOOGLE_CLIENT_SECRET);
  }
  return false;
}
```

- The registry is the single source of truth for what appears on the admin page.
- Adding a provider later means one registry entry + one auth route; no schema or page rewrite.
- Google readiness requires **both** `GOOGLE_CLIENT_ID` and `GOOGLE_CLIENT_SECRET` (per interview decision). Note: the GIS ID-token flow only verifies against the client ID; the secret is reserved for a future server-side code flow and is **never** sent to the browser. Completing both keeps the setup checklist unambiguous.

### 6.2 Data model

New `apps/server/src/models/integration.model.js`:

```js
{
  key: { type: String, required: true, unique: true, index: true }, // 'google'
  enabled: { type: Boolean, default: false },
  updatedBy: { type: mongoose.Schema.Types.ObjectId, ref: 'User', default: null },
}
// { timestamps: true }
```

- No document is created until the first toggle. Missing document ⇒ `enabled: false`.
- `updatedBy` is populated for the admin response (name/email only).

**User model additions** (`apps/server/src/models/user.model.js`):

```js
googleId:          { type: String },   // Google `sub`
googleEmail:       { type: String, lowercase: true, trim: true },
googleName:        { type: String, default: '' }, // snapshot only; never copied to fullName
googlePicture:     { type: String, default: '' },
googleLinkedAt:    { type: Date },
googleLastLoginAt: { type: Date },
```

- Add a sparse unique index: `userSchema.index({ googleId: 1 }, { unique: true, sparse: true });`
- `passwordHash` stays **required**. Because Google sign-up is rejected, every Google-capable account already has a password. No passwordless accounts are introduced.
- Do not change the existing `email` unique index. Google email matching uses the normalized (lowercase, trimmed) email.

**Audit log** (`apps/server/src/models/audit-log.model.js`):

- Add `'integration.update'` to the `action` enum.
- Keep the existing schema; no new fields required. Use `detail` for a readable summary.

### 6.3 Environment

Add to `apps/server/src/config/env.js` (both optional so the API still boots without Google):

```js
GOOGLE_CLIENT_ID: z.string().optional(),
GOOGLE_CLIENT_SECRET: z.string().optional(),
```

Add to `apps/server/.env.example`:

```dotenv

# Authorized JavaScript origin for local dev: http://localhost:5173
# GOOGLE_CLIENT_ID=xxxxx.apps.googleusercontent.com
# GOOGLE_CLIENT_SECRET=GOCSPX-xxxxxxxx
```

No redirect URI is required for the GIS popup/ID-token flow — only authorized JavaScript origins.

Add dependency to `apps/server/package.json`:

```
google-auth-library
```

(ESM-compatible; install with `pnpm --filter @healthcentria/server add google-auth-library`.)

## 7. API design

### 7.1 Public config — `GET /api/integrations/public`

Unauthenticated. Used by the header and login page. Reads the DB toggle and merges it with registry + env readiness.

Response `200`:

```json
{
  "success": true,
  "providers": [
    {
      "key": "google",
      "label": "Google",
      "enabled": true,
      "clientId": "1234567890-abc.apps.googleusercontent.com"
    }
  ]
}
```

Rules:

- `enabled` is the **effective** state: stored `enabled === true` **and** provider configured. If env vars disappear after enabling, this endpoint reports `enabled: false`.
- `clientId` is included only when `enabled` is true (client IDs are public; the secret is never returned).
- Disabled/unconfigured providers are still listed with `enabled: false` and no `clientId`; the UI simply ignores them.
- If MongoDB is not connected: `503 { success: false, message: "Database is not connected. Try again later." }`. The web client treats any failure as "disabled" and hides Google UI (fail closed).
- Send `Cache-Control: no-store`.
- Add a small in-memory cache is **not** required; one lightweight query per page mount is acceptable.

### 7.2 Admin list — `GET /api/admin/integrations`

Guarded by `requireAuth, requireRole('admin')`.

Response `200`:

```json
{
  "success": true,
  "integrations": [
    {
      "key": "google",
      "label": "Google",
      "description": "Let existing patients and staff sign in with their Google account.",
      "enabled": true,
      "configured": true,
      "effectiveEnabled": true,
      "clientIdHint": "…apps.googleusercontent.com",
      "stats": {
        "linkedAccounts": 12,
        "lastSignInAt": "2026-10-18T07:42:00.000Z"
      },
      "updatedAt": "2026-10-12T09:15:00.000Z",
      "updatedBy": { "id": "…", "name": "Clinic Admin" }
    }
  ]
}
```

- `enabled` = stored value; `configured` = both env vars present; `effectiveEnabled = enabled && configured`.
- `stats.linkedAccounts`: `User.countDocuments({ googleId: { $exists: true, $ne: null } })`.
- `stats.lastSignInAt`: max `googleLastLoginAt` across users, or `null`.
- `updatedAt` / `updatedBy`: from the integration document; both `null` if never toggled.
- `clientIdHint`: last 24 characters of the client ID prefixed with `…`; omit if unconfigured. (The full client ID is not needed in the admin UI.)
- `503` when DB is disconnected, matching existing controllers.

### 7.3 Admin toggle — `PATCH /api/admin/integrations/:key`

Guarded by `requireAuth, requireRole('admin')`.

Request:

```json
{ "enabled": true }
```

Zod schema: `{ enabled: z.boolean() }`, reject unknown body keys or empty body with `400`.

Behavior:

1. Unknown `key` ⇒ `404 { success: false, message: "Integration not found." }`.
2. `enabled: true` while `isProviderConfigured(key)` is false ⇒
   `409 { success: false, message: "Google sign-in is not configured. Add GOOGLE_CLIENT_ID and GOOGLE_CLIENT_SECRET to apps/server/.env, then restart the API." }`.
3. Upsert the document (`findOneAndUpdate({ key }, { $set: { enabled, updatedBy: req.user.id } }, { upsert: true, new: true, setDefaultsOnInsert: true, runValidators: true })`).
4. On a real state change, write an audit log:
   - `action: 'integration.update'`
   - `actor: req.user.id`
   - `detail: 'integration=google enabled=false->true'`
5. No-op (same stored value) returns `200` without a new audit entry.
6. Response `200 { success: true, integration: <same shape as list item> }`.

Turning **off** is always allowed, even when the provider is currently unconfigured.

DB errors: `503`; unexpected errors: existing `errorHandler` (500).

### 7.4 Google sign-in — `POST /api/auth/google`

Public. Request:

```json
{ "credential": "<Google ID token JWT>" }
```

Zod schema: `{ credential: z.string().min(20) }`.

Verification:

```js
const googleClient = new OAuth2Client(env.GOOGLE_CLIENT_ID);
const ticket = await googleClient.verifyIdToken({
  idToken: credential,
  audience: env.GOOGLE_CLIENT_ID,
});
const payload = ticket.getPayload();
```

`google-auth-library` validates signature, `aud`, `iss`, and expiry. Additional checks:

- `payload.email_verified === true`, otherwise `403` with "Your Google email is not verified. Verify it with Google and try again."
- `payload.email` must be present and normalize to a valid email.
- `payload.sub` is the stable Google key.

Step-by-step behavior:

1. `requireDB` check → `503` if disconnected.
2. Read stored toggle + configured state. If not effective-enabled ⇒
   `403 { success: false, message: "Google sign-in is currently disabled." }` (check this **before** verification; cheap and prevents unnecessary Google calls).
3. Verify the credential.
   - Token/audience/expiry errors ⇒ `401 { success: false, message: "Google sign-in could not be verified. Try again." }`; log the underlying error server-side only.
   - Network/DNS/timeout failures reaching Google ⇒ `503 { success: false, message: "Google sign-in is temporarily unavailable. Try again shortly." }`.
4. Find `User` by `googleId: payload.sub`:
   - Not active ⇒ `403 { success: false, message: "This account is inactive. Contact an administrator." }`.
   - Update `googleLastLoginAt`, `googleEmail`, `googlePicture`; save; issue session.
5. Else find by normalized `email`:
   - No user ⇒ `403 { success: false, message: "No HealthCentria account uses this Google email. Register as a patient or ask staff to create an account." }`.
   - Not active ⇒ same inactive message as above.
   - `googleId` exists and differs from `payload.sub` ⇒ `409 { success: false, message: "This account is already linked to a different Google account." }`.
   - Otherwise link: set `googleId`, `googleEmail`, `googleName`, `googlePicture`, `googleLinkedAt`, `googleLastLoginAt`. **Do not modify `fullName`.**
   - Catch duplicate-key `E11000` on `googleId` race ⇒ refetch by `googleId`; if the sub matches, continue, else `409`.
6. Return the exact same session payload as password login:
   `201/200 { success: true, token: <JWT>, user: { id, name, email, role } }`.
   Use the existing `signSession` and `publicUser` helpers; HTTP `200` is fine (no resource created on success).

Security notes:

- Verify `email_verified` before any linking; unverified Google emails must never be auto-linked.
- Google email is matched against the normalized account email; `User` schema already lowercases.
- The ID token is short-lived (≈1 hour) and single-use for this endpoint; no server-side token storage.
- No rate limiter is added in this scope; note as a future hardening item.

### 7.5 Route wiring

- `apps/server/src/routes/integration.routes.js`
  - `publicIntegrationRouter`: `GET /public`
  - `adminIntegrationRouter`: `GET /`, `PATCH /:key` with `requireAuth, requireRole('admin')`
- `apps/server/src/routes/index.js`:
  - `apiRouter.use('/integrations', publicIntegrationRouter)`
  - `apiRouter.use('/admin/integrations', adminIntegrationRouter)`
- `apps/server/src/routes/auth.routes.js`: add `authRouter.post('/google', googleLogin)`.

## 8. Frontend design

### 8.1 Shared API additions (`apps/web/src/lib/api.ts`)

```ts
export interface PublicIntegration {
  key: string;
  label: string;
  enabled: boolean;
  clientId?: string;
}

export function getPublicIntegrations(): Promise<{ success: true; providers: PublicIntegration[] }>;

export interface AdminIntegration {
  key: string;
  label: string;
  description: string;
  enabled: boolean;
  configured: boolean;
  effectiveEnabled: boolean;
  clientIdHint?: string;
  stats: { linkedAccounts: number; lastSignInAt: string | null };
  updatedAt: string | null;
  updatedBy: { id: string; name: string } | null;
}

export function listIntegrations(): Promise<{ integrations: AdminIntegration[] }>;
export function updateIntegration(key: string, input: { enabled: boolean }): Promise<{ integration: AdminIntegration }>;
```

- Extend `StaffAccount` with `googleLinked: boolean`.
- Keep `apiFetch` unchanged; these are admin-authenticated calls except the public one.

### 8.2 Google script loader (`apps/web/src/lib/google.ts`)

- Singleton `loadGoogleScript(): Promise<void>` injecting
  `https://accounts.google.com/gsi/client` (id `google-gsi-script`, `async`, `defer`).
- Reject if the script fails or does not define `window.google?.accounts?.id` within **8 seconds**.
- Minimal local TypeScript declarations for the GIS API (`initialize`, `renderButton`, `cancel`, `disableAutoSelect`) — do not add a types dependency.
- Export a `GoogleGlyph` component (inline official-colour "G" SVG) for the header and admin card. Do not add a binary logo asset.

### 8.3 Google sign-in hook/component

`apps/web/src/components/google-signin.tsx` (or `lib/use-google-signin.ts` + component):

- Props: `{ onCredential: (credential: string) => void; disabled?: boolean }`.
- On mount:
  1. Fetch public integrations (`getPublicIntegrations`). Any error ⇒ render nothing.
  2. If Google is `enabled` with a `clientId`, load the script, then `google.accounts.id.initialize({ client_id, callback, auto_select: false, ux_mode: 'popup' })`.
  3. `google.accounts.id.renderButton(container, { type: 'standard', theme: 'outline', size: 'large', text: 'continue_with', shape: 'pill', logo_alignment: 'left', width })`.
- Keep the credential callback in a ref so re-renders never initialize with a stale handler.
- Render button at the measured container width (clamped `200–400px`) and re-render on resize (`ResizeObserver`), so it fits the 320px-wide login card.
- Cleanup: clear the container, disconnect the observer; never re-inject the script.
- Script-failure fallback: render a small muted note "Google sign-in couldn't load. Use your email and password." after the 8s failure. Do not log the user out or block the password form.
- While a credential is being exchanged, show "Signing you in with Google…" and ignore duplicate credential callbacks (ref guard).
- The component owns no navigation; the page owns the session/navigate logic.

### 8.4 Auth client (`apps/web/src/lib/auth.ts`)

Add:

```ts
export async function loginWithGoogle(credential: string): Promise<AuthSession>;
```

- Uses the existing `postJson('/api/auth/google', { credential })` pattern (no circular import with `api.ts`).
- On `200/201`, build and store the session exactly like password login (`sessionFromApi`), then return it.
- On failure, throw an `Error` carrying the server `message` when present; otherwise a generic "Google sign-in failed. Try again." The page displays the message.
- Preserve the existing local-fallback behavior for password/register only — **never** create a local fallback session for Google. If the API is unreachable, Google sign-in fails visibly.

### 8.5 Login page (`apps/web/src/routes/login.tsx`)

- Add search validation: `validateSearch: () => ({ google: undefined as '1' | undefined })` (accept `?google=1`).
- Read `google` from `Route.useSearch()`.
- Fetch public config via the Google component; when enabled:
  - Render an "or" divider and the official Google button **above** the email/password form (primary SSO position) or below the submit button — implementation chooses one; keep the password form fully usable.
  - When `google === '1'` and the button is rendered, scroll the Google container into view and focus it (`tabIndex={-1}`) once. **Do not** auto-open the popup (browser popup blockers).
- Handler:
  ```ts
  async function handleGoogleCredential(credential: string) {
    setError(null); setPending(true);
    try {
      const session = await loginWithGoogle(credential);
      navigate({ to: roleDashboard(session.role) });
    } catch (err) {
      setError(err instanceof Error ? err.message : 'Google sign-in failed. Try again.');
    } finally { setPending(false); }
  }
  ```
- Reuse the existing role redirect mapping (`admin → /admin/dashboard`, `staff → /staff/dashboard`, else `/app/dashboard`).
- Display Google errors in the existing `role="alert"` block. For the "no account" error, the existing "Create an account" link covers the next step; no extra UI required.
- While Google sign-in is pending, keep the password submit disabled to avoid double navigation.
- If the integration is disabled mid-flow, the server error message is shown and the button disappears on the next public-config fetch/page reload. No client polling required.

### 8.6 Public header (`apps/web/src/components/public-header.tsx`)

- Fetch `getPublicIntegrations()` on mount (no cache; `cache: 'no-store'` on the fetch).
- When `google.enabled` is true, render a new link **before** "Log in":
  - Desktop: inline Google glyph + "Sign in with Google" (muted style, hover background, rounded-xl).
  - Mobile (`< sm`): glyph-only button with `aria-label="Sign in with Google"` to avoid crowding the header.
  - Target: `<Link to="/login" search={{ google: '1' }}>` — navigates to the login page and focuses the Google button; it does **not** start OAuth directly.
- When disabled, unconfigured, still loading, or the request fails: render nothing (no placeholder, no disabled state).
- No layout reservation; a small appearance shift after load is acceptable.
- Ensure the link does not render while a session already exists? The header is used on public pages only; keep it simple and render regardless (existing Log in/Register links are also always shown).

## 9. UX flows

### 9.1 Admin enables Google

1. Admin confirms `GOOGLE_CLIENT_ID` and `GOOGLE_CLIENT_SECRET` are in `apps/server/.env`; restarts the API.
2. Admin opens **Integrations**; Google shows "Off" + "Configured".
3. Admin flips the switch on → immediate save, chips update to "On", stats/last-changed refresh.
4. Audit entry `integration.update` is written.
5. Logged-out visitors now see "Sign in with Google" in the header and the official button on `/login`.

### 9.2 Admin disables Google

1. Admin flips the switch off → confirmation dialog.
2. Confirm → `PATCH`, chips update to "Off", audit entry written.
3. Header link and login button disappear on next page load. Anyone mid-session keeps their JWT until expiry (≤7 days).
4. Google-only accounts cannot re-authenticate until re-enabled; password login still works because every account has a password.

### 9.3 End-user Google sign-in

1. Visitor clicks the header link or the login page's Google button.
2. Google popup → chooses an account → GIS callback returns an ID token.
3. `POST /api/auth/google` validates the token, checks the toggle, links or finds the account, and returns the JWT.
4. The SPA stores the session and redirects by role.
5. Failure cases show a specific message in the login page's alert:
   - disabled integration, unverified email, unknown email, inactive account, conflicting link, verification/network failure.

### 9.4 First-time link

1. Existing account `juan@example.com` signs in with Google for the first time.
2. Server finds the account by email, stores Google identifiers and `googleLinkedAt`, sets `googleLastLoginAt`.
3. `fullName`, role, active flag, and password hash are untouched.
4. Subsequent Google sign-ins match by `googleId`. Email + password still works.

## 10. Error-handling matrix

| Situation | HTTP | Message (user-facing) |
| --- | --- | --- |
| Missing/short credential | 400 | Validation failed. |
| Toggle disabled | 403 | Google sign-in is currently disabled. |
| Bad/expired/wrong-audience token | 401 | Google sign-in could not be verified. Try again. |
| Google unreachable / network error | 503 | Google sign-in is temporarily unavailable. Try again shortly. |
| `email_verified` false | 403 | Your Google email is not verified. Verify it with Google and try again. |
| No matching account | 403 | No HealthCentria account uses this Google email. Register as a patient or ask staff to create an account. |
| Inactive account | 403 | This account is inactive. Contact an administrator. |
| Account linked to another Google sub | 409 | This account is already linked to a different Google account. |
| DB disconnected | 503 | Database is not connected. Try again later. |
| Enable without env credentials | 409 | Google sign-in is not configured. Add `GOOGLE_CLIENT_ID` and `GOOGLE_CLIENT_SECRET` to `apps/server/.env`, then restart the API. |
| Unknown provider key | 404 | Integration not found. |
| Non-admin calls admin integration API | 403 | Not allowed for your role. |
| Public config fetch fails on web | — | Hide Google UI silently (fail closed). |
| GIS script blocked/timeout | — | Google sign-in couldn't load. Use your email and password. |

Log verification failures and duplicate-key races with `console.error`/`console.warn` server-side; never return raw Google library errors.

## 11. Edge cases and invariants

- **No account auto-creation, ever.** Registration remains the only way to create a patient; admin Staff Accounts remains the only way to create staff/admin.
- **Every account has a password.** Because Google cannot create accounts, `passwordHash` remains required and disabling Google never locks anyone out permanently.
- **Email normalization** applies on both sides (lowercase + trim) before matching.
- **`email_verified` must be true.** Never link based on an unverified Google email.
- **Google email changes** are handled by matching `googleId` first; `googleEmail` is refreshed on each sign-in.
- **Deactivated accounts** are rejected on Google sign-in exactly like password login.
- **Role is never derived from Google**; the existing user document's role is used.
- **Link conflict:** if an account already has a different `googleId`, refuse; do not silently re-link.
- **Env removed after enabling:** public endpoint reports disabled, sign-in returns 403, admin card shows "On (paused)" and allows turning it off. No crash.
- **Toggle concurrency:** last write wins; each state-changing request writes its own audit entry. No optimistic-concurrency fields.
- **DB outage:** public config and Google auth fail closed; admin page shows an error and retry.
- **Existing sessions:** disabling does not revoke JWTs (chosen behavior; JWT is stateless with 7-day expiry).
- **Admin self-lockout is impossible** through this feature because password login is unaffected.
- **Secrets never leave the server.** `GOOGLE_CLIENT_SECRET` is never exposed through any API or bundled into the web app; only `GOOGLE_CLIENT_ID` is public.
- **Header/login consistency:** both read the same public endpoint; if it fails they both hide the UI.
- **CSP/COOP:** see §12.
- **No Google profile photo rendering**, so no remote image request is made for avatars.

## 12. Headers, CSP, and production notes

The SPA is currently served by Vite, so Express `helmet()` does not apply to `index.html`. Still, update `apps/server/src/app.js` so the API is correct if the built SPA is ever served by Express, and document the requirement for the production web host:

- `Content-Security-Policy`:
  - `script-src 'self' https://accounts.google.com/gsi/client`
  - `frame-src 'self' https://accounts.google.com`
  - `connect-src 'self' https://accounts.google.com`
  - keep the rest of helmet's defaults
- `Cross-Origin-Opener-Policy: same-origin-allow-popups` — helmet's default `same-origin` can break the Google popup handshake. Set via `helmet({ crossOriginOpenerPolicy: { policy: 'same-origin-allow-popups' } })`.
- Do **not** add a `googleusercontent.com` image exception unless profile photos are later displayed.

Google Cloud setup (for the README):

1. Create/select a Google Cloud project.
2. Configure the OAuth consent screen (External; add staff/admin emails as test users while in testing).
3. Create Credentials → OAuth client ID → **Web application**.
4. Authorized JavaScript origins: `http://localhost:5173` (and the production web origin, e.g. `https://healthcentria.example`). No redirect URI is needed for the GIS flow.
5. Copy the client ID and secret into `apps/server/.env`; restart the API.
6. Sign in as admin → **Integrations** → enable Google → verify with an incognito window.

## 16. Rollout / backward compatibility

- Both Google env vars are optional; existing deployments boot unchanged with Google off.
- New Mongo fields are additive; no migration script is required. The sparse unique index is created by Mongoose on startup (allow time for index build; `googleId` is absent on existing users).
- The new audit enum value is additive.
- No existing API response shape changes except `StaffAccount.googleLinked` (additive).
- Reverting the feature leaves harmless unused fields/documents behind; passwords and roles are untouched.
